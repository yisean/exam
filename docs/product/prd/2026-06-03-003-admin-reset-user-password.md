# PRD 003 · 管理端：管理员一键重置用户密码

## 1. 背景与问题

员工忘记登录密码时，目前没有管理端入口可恢复，只能由运维直接改数据库，流程重、易出错、不可审计。需要在「用户管理」里提供管理员一键重置密码的能力。

## 2. 目标 / 非目标

**目标**
- 管理员在「用户管理」列表对单个用户一键把密码重置为系统默认初始密码，二次确认后生效。

**非目标（本期不做）**
- 批量重置多个用户。
- 自定义重置后的密码值（一律重置为默认初始密码）。
- 强制用户首次登录后改密。
- 重置结果的短信/邮件/站内通知。

## 3. 用户与角色

- **超级管理员（sa）**：唯一可执行重置的角色。
- **teacher / assistant / student**：不可见、不可执行。

## 4. 关键决策

- 重置目标为**单个用户**，入口在用户管理列表的行操作区。
- 重置值为**系统默认初始密码**（与新建用户初始密码一致，当前取 `123456`）。
- 执行前**二次确认**，确认弹窗显示目标用户账号，避免误操作。
- 重置**只改密码**，不触碰该用户的角色、部门、状态等其它信息。

## 5. 功能需求（R）

- **R1** 「用户管理」列表每行提供「重置密码」操作入口。
- **R2** 该入口仅 `sa` 可见且可执行；其它角色不可见 / 不可达。
- **R3** 点击后弹出二次确认，确认弹窗显示目标用户账号；取消则不做任何变更。
- **R4** 确认后，将该用户密码重置为系统默认初始密码（`123456`），按既有加密方式存储。
- **R5** 重置成功给出成功提示；失败（用户不存在等）给出明确错误提示。
- **R6** 重置仅变更密码，不改变该用户的角色、部门、状态及其它字段。

## 6. 验收标准（AE）

- **AE1（R1/R2）** `sa` 登录，用户管理列表每行有「重置密码」按钮；`teacher` 登录时该按钮不可见 / 不可用。
- **AE2（R3）** 点击「重置密码」弹出二次确认且含目标账号；点「取消」后该用户密码不变。
- **AE3（R4）** 确认重置后，该用户可用默认密码 `123456` 成功登录。
- **AE4（R5）** 对不存在的用户执行重置，返回明确错误提示，不报未捕获异常。
- **AE5（R6）** 重置后，该用户的角色、部门、启用状态等与重置前一致。

## 7. 成功指标

- 管理员可在 ≤3 次点击内完成一次密码重置。
- 上线后「改数据库改密码」的人工运维请求降为 0。

## 8. 依赖与假设

- 复用现有 `sys_user` 表与密码加密工具 `PassHandler`；重置接口建议 `POST /exam/api/sys/user/reset-pwd`，`@RequiresRoles("sa")`。
- 前端在现有用户管理页 [`docs/engineering/prototype/sys-user.html`](../../engineering/prototype/sys-user.html) 增加行内「重置密码」+ 二次确认弹窗。
- 假设默认初始密码取 `123456`（与新建用户一致）；若系统已存在「默认密码」配置项则复用该配置。

## 9. 待解决问题

- 默认初始密码是否需要做成可配置项（`sys_config`）？本期按固定 `123456` 处理。
- 是否需要「强制用户下次登录改密」？本期列为非目标，后续可经 `/spec-change` 增量。
