# PRD：考试助理与预约考试

## 1. 背景与问题

企业每季度组织一次员工考核。当前考试的「开放范围 + 时间」由超级管理员 / 老师（`sa`/`teacher`）集中安排：哪个部门在什么时间考，全靠中心管理员逐个部门对接排期。当部门多、各部门作息不同（客服轮班、生产早晚班等）时，集中排期既要管理员掌握各部门可考时间，又难以让部门表达偏好，协调成本高。

本特性把「挑哪个时段考」下放给部门自己的协调人——**考试助理**：管理员只开出若干可预约时段并设容量，各部门自助认领，去掉中心化排期的来回沟通；考试本身仍由 `sa`/`teacher` 统一掌控。

> 对应策略：[`STRATEGY.md`](../STRATEGY.md) 中「多角色考试流程」轨道——补齐 `sa`/`teacher`/`student` 之外的「考试助理」角色与「预约考试」能力。

## 2. 目标与非目标

### 目标
- 让部门考试助理自助为本部门（含所有下级）认领考试时段，无需管理员逐部门排期。
- 管理员对一场考试可配置多个时间段，每段独立控制开放类型与起止时间。
- 应考资格在开考时按部门树动态判定，人员变动（入职/转岗/离职）自动生效，契合「装完免维护」取向。

### 非目标
- 员工个人自助预约（员工自己挑时段去考）——预约只到**部门级**。
- 线下考场 / 座位 / 机位的预约与容量管理。
- 考试助理代员工报名 / 报名审核流程。
- 预约相关通知与提醒（站内信 / 短信 / 邮件）——系统当前无通知设施。
- 预约统计报表 / 看板；满额后的候补 / 排队。

## 3. 目标用户与角色

| 角色 | 标识 | 在本特性中的职责 |
| --- | --- | --- |
| 超级管理员 / 老师 | `sa` / `teacher` | 创建与管理考试、为考试配置时间段及其类型；为「指定部门」时段勾选部门，为「预约考试」时段设可预约部门数上限、可选「免预约部门」与提前可见时长 |
| **考试助理（新增）** | `assistant` | 代表的部门即其账号所属部门（`depart_id`）；登录后查看含预约型时段的考试，代表本部门（含所有下级）预约 / 取消 / 改约。一个部门可有多名助理 |
| 学员（员工） | `student` | 在所属部门被预约的时段窗口内参加考试 |

## 4. 关键产品决策

- **预约最小单位是「部门」，不是个人。** 助理代表本部门预约，成功即代表该部门全员应考。
- **预约的部门含其所有下级。** 助理绑定一个部门，预约连同组织树下所有子部门一并纳入。
- **参考名单开考时动态计算，而非预约时快照。** 谁在被预约部门（含下级）且处于时段窗口内即可考；人员变动自动生效，无需维护名单。
- **时段容量按「可预约部门数」封顶，而非人数。** 容量与人数解耦，部门预约后扩编不与容量冲突。
- **时间段是独立于考试的实体。** 开放类型与起止时间下沉到时段层；三种开放类型（不限人员 / 指定部门 / 预约考试）等价于把现有 `el_exam.open_type`（公开/部门/定员）抬升到时段层。
- **助理代表的部门即其账号所属部门**（`depart_id`），不额外配置绑定；一个部门可有多名助理。
- **时间只在时段层级控制，考试不设总可考期。** 另设可配置的「提前可见」时长（如 5 / 10 分钟），时段开始前该时长内即可见考试；预约截止点为时段开始时刻。
- **「预约考试」时段可叠加「免预约指定部门」。** 被指定部门无需预约即可参加，可预约名额供其余部门助理认领；两类部门成员都计入应考人。

## 5. 功能需求

> 编号沿用需求文档（brainstorm）以便追溯。

### 5.1 考试时间段（管理端 `sa`/`teacher`）
- **R1** 一场考试可配置一个或多个时间段，每段独立记录起止时间；考试本身不设总可考期。
- **R2** 每个时间段有开放类型：不限人员 / 指定部门 / 预约考试。
- **R3** 时间段的增删改仅由 `sa`/`teacher` 完成；助理不能创建或修改时间段。
- **R4** 「预约考试」时段须设**可预约部门数上限**（正整数）。
- **R4b** 「指定部门」时段须以组织树勾选一个或多个部门（勾选部门含其所有下级）。
- **R4c** 系统提供可配置的「提前可见」时长（如 5 / 10 分钟），学员与助理在时段开始前该时长内即可见对应考试。
- **R4d** 「预约考试」时段可选地以组织树指定若干「免预约部门」（含下级）：无需预约即可参加；可预约部门数上限只约束其余需预约的部门。

### 5.2 预约（考试助理）
- **R5** 助理登录后能看到「至少含一个『预约考试』时段、且可供其部门预约」的考试。
- **R6** 助理只能为自己所属部门预约；范围自动包含该部门所有下级。
- **R7** 一个部门在同一场考试中只能预约一个时段。
- **R8** 预约成功占用该时段一个部门名额；达到上限后该时段不可再被其他部门预约。
- **R9** 预约截止点为时段开始时刻；时段一旦开始即不可再预约（入口/按钮禁用）。
- **R10** 时段开始前，助理可取消本部门预约，取消后释放占用的部门名额。
- **R11** 时段开始前，助理可改约到同一考试的另一未满「预约考试」时段（等效取消原约 + 约新时段，受目标时段容量约束）。
- **R11b** 每条预约记录保存预约人（操作助理）与预约时间；`sa`/`teacher` 可在时段名额处查看已预约部门及其预约人、预约时间。

### 5.3 应考（学员）
- **R12** 「预约考试」时段：学员属于（已预约该时段的部门 或 被指定的免预约部门，均含下级）且处于时段窗口内时可参加。
- **R13** 「指定部门」时段：学员属于该时段勾选部门（含下级）且处于窗口内时可参加。
- **R14** 「不限人员」时段：不限定参考人员，窗口内开放参加。
- **R15** 参考资格在开考/答题时点动态判定，跟随员工部门归属与时段窗口实时变化。

### 5.4 管理端预约管理（增量，2026-06-01）

> 来源 [admin-booking-management brainstorm](../brainstorms/2026-06-01-admin-booking-management-requirements.md)。在 R11b「查看」基础上补齐管理端的可见性 UI 与取消干预。

- **R16** 管理端在「修改考试」页的时段表中，对每个「预约考试」时段提供「查看预约」入口，弹窗列出该时段已预约的部门、预约人、预约时间（R11b 的 UI 落地）。
- **R17** `sa`/`teacher` 可取消任意部门的预约并释放名额；管理员**不受 R10「时段开始前」限制**——已开始 / 已结束时段的预约也可取消。
- **R18** 取消前，若被取消部门（含下级）在本场考试已有学员试卷（进行中或已交卷），须二次确认；取消仅释放名额、阻止该部门**之后**开考，**不删除**已有试卷与成绩（资格动态判定，天然成立）。
- **R19** 查看与取消对 `sa` 与 `teacher` 均开放（既有 R11b 的 `slot-bookings` 由 `sa` 放宽为 `sa`/`teacher`；考试 `save` 仍限 `sa`，为既有不一致，不在此改）。

> 非目标（承接 brainstorm）：取消通知/提醒、取消原因与审计记录、管理员代部门预约/指派 —— 均不做。

## 6. 关键用户流程

**管理员开出预约时段**
1. 创建/编辑考试 → 添加时间段 → 选类型「预约考试」→ 设起止时间 + 可预约部门数上限（+ 可选免预约部门、提前可见时长）→ 保存。

**助理认领时段**
1. 助理登录 → 看到含可预约时段的考试 → 在某未满时段点「预约」→ 占用一个部门名额。
2. 时段开始前可「取消」释放名额，或「改约」到另一未满时段。
3. 时段开始 → 该时段预约入口禁用。

**员工应考**
1. 进入时段窗口（含提前可见时长）→ 系统按部门树动态判定资格 → 符合者可作答。

**管理员查看/取消预约（增量）**
1. 修改考试 → 时段表某「预约考试」时段点「查看预约」→ 弹窗见已约部门/预约人/时间。
2. 对某行点「取消」→ 若该部门已有学员试卷则二次确认 → 释放名额；已交卷成绩不受影响。

## 7. 验收标准

> 沿用需求文档 Acceptance Examples。

- **AE1（R6/R12/R15）** 助理属「技术部」（下含前端组/后端组）。预约某时段后，前后端组所有在岗员工在该时段窗口内均可考，窗口外不可考。
- **AE2（R8）** 某时段上限 3 个部门且已约满。第 4 个部门助理打开时该时段显示已满、不可预约；其余未满时段仍可约。
- **AE3（R10/R11）** 部门已约时段甲，开始前改约到时段乙：甲释放一个名额，部门改占乙一个名额；若乙已满则改约失败。
- **AE4（R7）** 某部门已约时段甲后再约同考试时段乙，系统拒绝。
- **AE5（R9）** 时段甲到开始时刻后，助理再打开时甲的预约入口已禁用。
- **AE6（R12/R15）** 部门预约后新入职员工被分到该部门，开考时自动具备资格，无需助理重新维护名单。
- **AE7（R16/R19）** `sa` 或 `teacher` 在某预约型时段点「查看预约」，弹窗显示已约部门、预约人姓名、预约时间。
- **AE8（R17/R18）** 管理员取消一个已有学员交卷部门的预约：弹二次确认；确认后名额释放、该部门未开考学员失去入口，已交卷成绩与记录仍在。即使时段已开始也可取消。

## 8. 成功指标

- **考试完成率**（核心，来自策略）——预约自助化后部门应到/实到比例不下降。
- **管理员排期工时**——单场考试管理员用于排期/沟通的时间显著下降（定性即可，系统无埋点）。
- **预约自助率**——通过助理自助认领完成的时段占比（相对管理员手工指定）。

## 9. 依赖与假设

- 依赖现有组织结构（`sys_depart` 部门树）与角色体系（`sys_role` / `sys_user_role`）；「考试助理」作为新增角色接入现有 Shiro + JWT 权限模型。
- 假设系统能基于部门树解析「某部门及其所有下级」的成员集合，用于「指定部门」勾选与开考动态判定。
- 现有 `el_exam` 单一 `open_type` 与起止时间在引入时间段实体后的过渡方案，由实现计划确定，见 [plan 001](../../engineering/plans/2026-05-29-001-feat-exam-assistant-booking-plan.md)。

## 10. 待解决问题

- 「指定部门」时段的勾选部门是否含下级（默认含，与预约口径一致，待确认）。
- 现有 `el_exam.open_type` 与单一起止时间在引入时间段实体后的过渡/兼容方案。
- 「提前可见」时长是全局系统配置（`sys_config`）还是按考试/时段配置。
