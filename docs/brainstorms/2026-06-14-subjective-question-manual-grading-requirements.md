# 简答题与人工阅卷

## Summary

新增独立「简答题」(type 4)，可入题库、参与组卷与作答；含简答的试卷交卷后进入「待阅卷」，由 sa/teacher 整份阅卷、逐题打分并写文字点评，提交后系统重算总分（客观自动分 + 主观人工分）、判定通过与否，考生即时可见成绩与点评。

## Problem Frame

系统当前只支持客观题（单选/多选/判断/不定项/综合），交卷即自动判分、即时出分。但原作者在底层**预留了主观题与人工阅卷的骨架，却从未接通**：试卷状态枚举里有「待阅卷 WAIT_OPT」、`el_paper_qu` 有 `answer`（主观答案）和 `actual_score`（实际得分(主观题)）字段、`ExamController` 有「待阅卷列表 review-paging」接口——但题型枚举里没有简答题，`PaperController` 里也没有任何打分/阅卷接口，前端没有阅卷页。

后果是：这条主观题链路是断的。一旦出现需要人工评分的题，试卷会永远卡在客观自动判分这一步，无法收尾。对企业培训这类常需简答/问答考核的场景，这是一个能力缺口；而由于骨架已在，补全的代价远小于从零新建。

本特性把这套预留骨架接通成完整闭环：录题 → 组卷 → 作答 → 人工阅卷 → 算分出分。

## Key Decisions

- **只做独立简答题，综合题保持纯客观。** 简答作为独立 type 4，可入题库、组卷、单独成题；综合题的 5 个子题仍限客观题型，其「全自动判分」逻辑完全不动。把改动面收到最小，避免触碰已上线的综合题判分链。
- **按整份试卷阅卷，而非按题集中阅卷。** 阅卷人打开某考生的一份试卷，依次给其中所有简答题打分后整份提交。直接复用现有「待阅卷试卷列表」，不引入按题聚合的查询与页面。
- **阅完即可见，不做「统一发布成绩」流程。** 阅卷人提交一份卷后，该考生立即可见总分与逐题结果，与现有客观卷「交卷即出分」的体验一致；不引入额外的成绩发布状态与操作。
- **单题得分按整数。** 沿用现有 `actual_score` 为 `Integer` 的设计，阅卷打分取 0..该题满分 的整数；不支持半分/小数分。
- **复用 WAIT_OPT 状态贯穿流转。** 含简答的试卷交卷后进入待阅卷；纯客观卷维持交卷即「已完成」不变。

## Actors

- A1. **考生 (student)** — 作答简答题（文本输入）；阅卷完成后查看成绩、逐题结果与老师点评。
- A2. **阅卷人 (sa / teacher)** — 在待阅卷列表中打开试卷，逐题给简答打分、写点评，整份提交。
- A3. **录题/组卷人 (sa / teacher)** — 创建/编辑简答题（题干、参考答案、解析、分值）；在考试配置中可选地纳入简答题。

## Key Flows

- F1. 录入简答题
  - **Trigger:** 录题人在试题管理新增题目，题型选「简答题」。
  - **Steps:** 填写题干、参考答案、解析、分值（无选项）；保存进题库，可被考试组卷引用。
  - **Covered by:** R1, R2

- F2. 考生作答含简答的试卷
  - **Trigger:** 考生开始一场含简答题的考试。
  - **Steps:** 答题卡按题型分组展示，简答题渲染为文本输入框；作答内容实时保存到该题的主观答案；交卷。
  - **Outcome:** 客观题自动判分；因含未判的简答题，试卷进入「待阅卷」，总分暂不产出，成绩列表显示「待阅卷」。
  - **Covered by:** R3, R4, R7

- F3. 阅卷人整份阅卷
  - **Trigger:** 阅卷人在「待阅卷试卷列表」打开一份试卷。
  - **Steps:** 查看每道简答题的题干、考生作答、参考答案与解析；为每题录入得分（0..该题满分）与可选文字点评；整份提交。
  - **Outcome:** 系统按 R6 重算总分、判定通过与否，试卷转「已完成」，考生即时可见。
  - **Covered by:** R5, R6, R7, R8

## Requirements

**题型与录题**

- R1. 新增简答题题型（type 4），与现有题型并列，可在试题管理中创建、编辑、删除、按题型筛选。
- R2. 简答题录题字段含题干、参考答案、解析、分值；无选项。题干/参考答案/解析的最大字符数在 PRD 阶段按业务定值并前后端一致校验。
- R2b. 简答题可被加入题库，并像其他题型一样参与考试组卷与抽题。
- R2c. 考试组卷时简答题为可选项：简答题数量可配置为 0，不强制每场考试都包含简答题；为 0 时该考试等同纯客观卷，按 R7 走「交卷即完成、即时出分」。

**作答**

- R3. 考生端答题界面支持简答题：渲染为多行文本输入框，按现有答题卡分组规则归入「简答题」一组，支持已答/未答标记与跳转。
- R4. 简答题作答内容随作答实时保存到该题的主观答案；「已答」判定为作答文本非空。

**阅卷**

- R5. 提供整份试卷阅卷能力：阅卷人可打开一份待阅卷试卷，看到其中每道简答题的题干、考生作答、参考答案、解析，并为每题录入整数得分（0..该题满分）与可选文字点评，整份提交。
- R5b. 阅卷提交时校验每道简答题得分均已录入且在 [0, 该题满分] 区间内；越界或漏评不予提交并给出提示。

**算分与状态流转**

- R6. 试卷总分 = 客观题自动得分 + 各简答题人工得分之和；阅卷提交后按总分与该考试及格线判定通过/不通过。
- R7. 含简答题的试卷交卷后进入「待阅卷」状态，此时不产出总分；阅卷整份提交后转「已完成」。纯客观试卷维持交卷即「已完成」、即时出分，不受影响。
- R7b. 纯简答（无客观题）的试卷同样适用：交卷后客观得分为 0，整卷进入待阅卷，阅卷后出分。

**成绩呈现与权限**

- R8. 阅卷提交后，考生即时可在成绩列表/成绩详情看到总分、逐题得分、参考答案与老师点评。
- R9. 阅卷打分能力限 sa 与 teacher；二者均可阅任意待阅卷试卷。
- R10. 待阅卷列表/阅卷入口对 sa、teacher 可见；考生端无阅卷入口。

## Acceptance Examples

- AE1. **Covers R6, R7.** 一场 100 分考试 = 客观题 70 分 + 2 道简答各 15 分。考生客观题自动得 55，交卷后试卷为「待阅卷」、成绩列表显示「待阅卷」、不显示总分。阅卷人给两道简答 12 与 9，提交后总分 = 55 + 12 + 9 = 76，与及格线比对判定后试卷转「已完成」。
- AE2. **Covers R2c, R7.** 一场组卷时简答题数配置为 0 的考试（纯客观），考生交卷后试卷直接「已完成」并即时出分，不进入待阅卷（行为不变）。
- AE3. **Covers R7b.** 一场纯简答考试（无客观题），考生交卷后客观得分为 0、整卷「待阅卷」；阅卷出分后转「已完成」。
- AE4. **Covers R5b.** 阅卷人对某简答（满分 15）误填 18 或留空即点提交，系统拒绝提交并提示该题得分非法/未评。
- AE5. **Covers R8.** 阅卷人整份提交后，该考生刷新成绩即可看到总分、每道简答的得分与老师点评；无需管理员额外发布。

## Scope Boundaries

**首期不做（可后续迭代）**

- 综合题包含简答子题（综合题维持纯客观 5 子题）。
- 按题集中阅卷（一次看全体考生同一题）。
- 论述题等其他主观题型细分（简答已覆盖文本作答需求）。
- 简答题的 Excel 批量导入/导出（沿用 004 对新题型导入的推迟，首期仅手工录题）。
- 半分/小数分；统一「发布成绩」流程。

**明确排除（本次定调）**

- 简答题不纳入错题本与错题训练：错题本现为客观题「对/错」二值采集，简答无明确对错，不参与采集。
- 成绩公开后不允许改分：试卷阅完即「已完成」且考生已可见，首期不支持对已公开分数的二次回改（如确需纠错，作为后续独立议题）。
- teacher 阅卷不按「考试归属」隔离：不为考试新增创建人/归属字段，sa 与 teacher 一视同仁可阅全部待阅卷。

## Dependencies / Assumptions

- 复用已存在的底层资产：`PaperState.WAIT_OPT`（待阅卷）、`el_paper_qu.answer`（主观答案）与 `el_paper_qu.actual_score`（实际得分(主观题)）、`ExamController` 的待阅卷列表接口。
- 预计需要的最小数据变更：题型枚举新增 type 4；`el_paper_qu` 新增一个「点评/批注」字段（具体表/字段设计在设计与计划阶段定）。
- 假设现有交卷流程已具备「含主观题→置为待阅卷、纯客观→直接完成」的分支判断位（待 PRD/设计阶段核验，若无则需补）。
- 假设成绩详情页已具备逐题渲染框架，扩展简答题展示（作答/参考答案/解析/点评）即可，不新建结果页。
