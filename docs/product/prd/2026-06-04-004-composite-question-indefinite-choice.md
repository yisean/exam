# 004 综合题与不定项题型 · PRD

## 1. 背景与问题

当前试题管理（`exam-api` 的 `qu` 模块 + `exam-vue` 的 `src/views/qu`）只支持三种客观题型：单选（`RADIO=1`）、多选（`MULTI=2`）、判断（`JUDGE=3`），均为「原子题」——一题一干、若干选项、按选项 `isRight` **全对才得分（非对即错）**。题型定义见 [`QuType.java`](../../../exam-api/src/main/java/com/yf/exam/modules/qu/enums/QuType.java)，判分逻辑见 [`PaperServiceImpl.fillAnswer`](../../../exam-api/src/main/java/com/yf/exam/modules/paper/service/impl/PaperServiceImpl.java)，客观分汇总见 `PaperQuMapper.sumObjective`（`WHERE is_right=true` 才累加）。

客户提出两个缺口：

1. **缺少「不定项」题型**：现实考试中常有「正确答案为 1 个或多个、考生不知道有几个」的题。现有多选题是「全对才得分」，不能表达不定项常见的**部分给分**判法。
2. **缺少「综合题」**：客户希望把围绕同一段材料的多个小题组织在一起——一个综合题固定带 **5 个子题**，子题可以是单选/多选/判断/不定项，但子题本身不能再是综合题。系统目前题目不可嵌套，无法表达这种「父题 + 子题」结构。

本特性在试题管理中新增**不定项**题型，并新增**综合题**这一可嵌套子题的容器题型，覆盖「录题 → 组卷 → 作答 → 自动判分 → 成绩/解析」全链路。**注意：部分给分会把判分从「非对即错」升级为「可计算部分分」，并要求修正客观分汇总口径——这是本特性的主要工程改动点（见 §4 决策 1、§6）。**

## 2. 目标 / 非目标

### 目标
- 新增**不定项**题型：客观题，正确答案数量不固定（≥1），采用**固定半分制部分给分**自动判分。
- 新增**综合题**题型：含一段**共享题干/材料**（可含图片）+ **恰好 5 个子题**；子题题型为单选/多选/判断/不定项之一，禁止嵌套综合题。
- 综合题与不定项可正常进入**组卷 → 考试 → 自动判分 → 成绩/解析**：综合题作为一个整体抽取单位进卷，得分为其 5 个子题实得分之和。
- 判分引擎与客观分汇总支持「部分得分」，并在答卷/解析中展示「对 / 错 / 部分对 + 实得分」。
- 试题管理列表/筛选/编辑/删除支持这两种新题型。

### 非目标
- **不修改**现有单选/多选/判断/主观题（type 4）的录入与判分规则，存量试题与试卷判分行为不变。
- 子题**不支持**再嵌套综合题；综合题子题数量**不可配置**（固定 5）。
- **不做** Excel/批量导入对不定项与综合题的支持（本期沿用现有导入能力，不为新题型扩展）。
- **不做**子题分值的「组卷统一配分」模式——采用「子题自带分值、综合题随题携带总分」（见 §4 决策 2）。
- 不改造主观题（type 4）相关功能与人工阅卷流程。

## 3. 用户与角色
- **出题人 / 管理员（`sa` / `teacher`）**：录入/编辑/删除不定项与综合题（含为每个不定项题、子题设置分值）；组卷时配置不定项与综合题的抽取数量与分值。沿用现有试题管理权限，不新增角色。
- **考生（`student`）**：作答不定项题；在综合题中看到共享材料并逐个作答 5 个子题；在成绩/解析中看到部分得分。
- **系统（自动判分）**：提交试卷后对不定项（部分给分）与综合题（子题实得分汇总）**自动**判分并计入客观分，无需人工阅卷。

## 4. 关键决策

1. **不定项采用「固定半分制」部分给分**（非沿用多选「全对才得分」）。满分为该题/子题分值，规则见 R10：
   - 全部且**仅**选中所有正确项 → **满分**；
   - 选对但不全（漏选，且**无**错选）→ **满分的一半（固定，与漏几个无关）**，半分除不尽时**向下取整**、单题最低 0 分；
   - 选中**任一**错误项 → **0 分**。
   - 这要求判分引擎从「非对即错（整题满分 / 0 分）」升级为「**按题型算出实得分**」，并修正客观分汇总（见 §6 数据一致性）。
2. **综合题作为一个整体抽取单位进卷，分值 = 5 个子题分值之和**：组卷新增「综合题数量」配置；每个子题在录题时**各自携带分值**，综合题总分即子题分值之和，整题分值随题进卷（区别于现有「按题型统一配分」）。综合题得分 = 5 个子题各自**实得分**之和。
3. **综合题含共享材料**：父题持有一段共享题干/材料文本（可含图片），5 个子题展示在材料之下、共用该材料。
4. **子题固定 5 个、题型四选一、禁止嵌套**：子题题型 ∈ {单选, 多选, 判断, 不定项}，每个子题按其题型沿用既有录入校验（单选恰 1 个正确答案、判断为正确/错误两项、多选/不定项 ≥1 个正确答案）。
5. **不定项与综合题客观子题计入客观题统计**：现有客观题判分/汇总以 `qu_type < 4` 为口径，新题型的整数编码与该口径必须协调，确保不定项、综合题客观子题被自动判分并计入客观总分（具体编码取值留待 plan）。

## 5. 功能需求（R/F，续编不重排）

### 录题（试题管理）
- **R1** 作为出题人，我想在试题管理中新增「不定项」题型（可设置 1 个或多个正确答案），以便录入答案数量不固定的客观题；列表与编辑应能筛选、回显该题型。
- **R2** 若题型为不定项，则系统应要求至少 2 个选项且至少 1 个正确选项（正确选项无上限），否则拒绝保存并提示原因。
- **R3** 作为出题人，我想新增「综合题」，它包含一段共享题干/材料（可含图片）与恰好 5 个子题，以便把围绕同一材料的多个小题组织在一起。
- **R4** 在综合题编辑期间，系统应限定子题数量**恰好为 5**（不可多、不可少），数量不为 5 时不允许保存并提示。
- **R5** 若添加或编辑子题，则子题题型只能是单选/多选/判断/不定项之一，系统应禁止把子题设为综合题（禁止嵌套）。
- **R6** 作为出题人，我想为每个子题独立录入题干、选项、答案、解析与**分值**，且每个子题按其题型遵循对应录入校验（单选恰 1 个正确答案、判断为正确/错误两项、多选/不定项 ≥1 个正确答案），以便子题各自成题。
- **R7** 作为出题人，我想在试题列表中按「不定项」「综合题」筛选、查看、编辑、删除这些题；删除综合题时其 5 个子题一并级联删除，以便统一管理。

### 组卷与考试
- **R8** 作为管理员，我想在组卷时按「综合题」配置抽取数量，综合题作为一个整体抽取单位进入试卷（其 5 个子题随之进卷），以便把综合题纳入考试。
- **R9** 作为考生，我想在作答时看到综合题的共享材料并逐个作答其 5 个子题，以便完成综合题。

### 判分与成绩
- **R10** 当考生提交含不定项题的试卷时，系统应按「固定半分制」自动判分：全部且仅选中所有正确项得满分；选对但不全且无错选时得满分的一半（向下取整、最低 0 分）；选中任一错误项得 0 分。
- **R11** 当考生提交含综合题的试卷时，系统应将综合题得分计为其 5 个子题各自**实得分**之和（子题按各自题型判分，不定项用 R10 规则），综合题分值为 5 个子题分值之和。
- **R12** 不定项题与综合题（含其客观子题）作为客观题应被系统自动判分并计入试卷客观题总分，不依赖人工阅卷；**含部分得分的题（实得分大于 0 但小于满分）也须被计入总分**。
- **R13** 作为考生/出题人，我想在答卷/解析回顾中看到不定项与综合题子题的「对 / 错 / 部分对」状态及其**实得分**，以便理解得分构成。

## 6. 非功能约束
- **兼容性**：现有单选/多选/判断/主观题的录入、组卷、判分行为不得改变；存量试题与试卷不受影响。
- **判分模型一致性（重点）**：判分从「非对即错」升级为「可算部分分」后——
  - 客观分汇总不得再以 `is_right=true` 为唯一累加条件（否则「部分对」的题 `is_right=false` 会被漏算）；须按**实得分**累加，或引入「部分对」状态使其计入；
  - 同一份卷重复判分结果一致（确定性）。
- **数据完整性**：综合题与其 5 个子题为父子结构，删除综合题须级联删除子题；子题不得脱离父题独立存在于试题列表。
- **权限**：沿用现有试题管理鉴权（`sa` / `teacher`），不新增权限点。
- **依赖**：不引入新第三方依赖；遵循 [`conventions.md`](../../engineering/conventions.md) 的命名/分层/前端约定。
- **数据库变更**：落 `docs/ops/install/migration-2026-composite-question.sql`，与 plan 的 ER 模型一致。

## 7. 验收标准（AE/AC，每条标注覆盖的需求号）
- **AE1（R1）** 试题新增页题型下拉含「不定项」；选择后可录入 ≥2 个选项并勾选 ≥1 个正确答案，保存成功；列表可按「不定项」筛选，编辑回显题型为不定项。
- **AE2（R2）** 不定项录入时若正确选项为 0 个或选项少于 2 个，保存被拒绝并提示原因；满足条件则保存成功。
- **AE3（R3）** 能创建一个综合题：填写共享材料文本（并可上传材料图片）+ 5 个子题，保存成功，列表显示为综合题且可查看共享材料。
- **AE4（R4）** 综合题子题为 4 个或 6 个时保存被拒绝并提示「子题必须为 5 个」；恰好 5 个时可保存。
- **AE5（R5）** 子题题型可选项中**不包含**「综合题」，无法将子题设为综合题。
- **AE6（R6）** 某子题为单选却含 2 个正确答案时保存被拒；判断子题自动具备「正确/错误」两项；不定项子题 0 个正确答案时保存被拒；各子题分值可分别设置并保存。
- **AE7（R7）** 列表可按「不定项」「综合题」筛选；删除一个综合题后，其 5 个子题在题库中一并被删除，列表不再出现该综合题及其子题。
- **AE8（R8）** 组卷配置中可设「综合题」抽取数量为 N，生成试卷时恰好包含 N 个综合题，每个携带其 5 个子题。
- **AE9（R9）** 考生作答页：综合题显示共享材料，且 5 个子题可逐一作答并随卷提交。
- **AE10（R10）** 一道满分 10 分的不定项（固定半分制）：
  - 正确项 {A,C}，选 {A,C} → 10 分；选 {A} → 5 分（漏选、无错选，固定一半）；
  - 正确项 {A,C,E}，选 {A} → 5 分；选 {A,C} → 5 分（漏选一律半分，与漏几个无关）；
  - 选 {A,B}（B 为错项）→ 0 分；选 {A,C,D}（D 为错项）→ 0 分。
- **AE11（R11）** 一个综合题含 5 个子题、每题 2 分共 10 分：子题①单选答对得 2 分、子题②不定项漏选得 1 分（满分 2 的一半）、子题③④⑤答错得 0 分 → 综合题得 **3** 分（各子题实得分之和）。
- **AE12（R12）** 含不定项与综合题的试卷提交后，系统自动给出客观分；不定项与综合题客观子题的**实得分（含部分分）**正确计入客观题总分，无需人工阅卷。
- **AE13（R13）** 答卷/解析回顾中，不定项与综合题各子题显示「对 / 错 / 部分对」状态及实得分，与 AE10、AE11 的判分结果一致。

## 9. 成功指标
- 出题人能成功创建：① 一道不定项题（含分值）；② 一个含 5 个混合题型子题（含不定项）的综合题，并将综合题纳入一场考试。
- 考生作答后，系统对不定项（固定半分制）与综合题（子题实得分汇总）**自动**得出正确客观分，含部分得分的题正确计入总分，§7 全部 AE 通过。
- 现有单选/多选/判断题的录入与判分回归无新增问题。

## 10. 依赖与假设
- 依赖现有 `qu`（试题）、`paper`（试卷/判分）、`exam`（考试/组卷 `ExamRepo`）模块。
- 假设综合题的「整体抽取单位 + 子题随题进卷」可在现有组卷流程（`PaperServiceImpl.generateByRepo`）与考试配置端扩展实现。
- 假设综合题父子结构可复用 `Qu` / `QuAnswer` 实体并新增父子关联（具体 ER 与字段在 plan 阶段确定），并落 DB migration。
- 假设前端题型下拉、筛选过滤器（`exam-vue/src/filters/index.js`）、录题表单（`form.vue`）、答卷/解析页可扩展承载新题型、子题编辑器与部分得分展示。

## 11. 待解决问题
- **半分取整方式**：固定半分制中「满分的一半」除不尽时默认**向下取整、单题最低 0 分**（如满分 5 分漏选得 2 分）；是否改为四舍五入或允许小数分，待客户/产品确认。
- **不定项 / 综合题的组卷配分**：本 PRD 采用「不定项按题型配分、综合题随子题携带总分」；是否需要在组卷端为综合题统一配分（覆盖子题分值），留待 plan 评估，默认不做。
- **题型整数编码取值**：不定项与综合题的 `quType` 取值留待 plan，需保证不定项及综合题客观子题计入 `qu_type < 4` 之类的客观题统计口径（见 §4 决策 5）。
- **批量导入**：Excel 批量导入是否需支持不定项/综合题，默认本期非目标。
- **综合题进入题库的方式**：综合题与子题如何归属题库（`QuRepo`）——按父题归属还是父子各自归属，留待 plan。
- **解析回顾展示细节**：综合题材料折叠、子题逐题对错与解析的具体版式在原型阶段细化。
