# 管理端预约查看与取消 需求文档

## Summary

为「预约考试」补齐管理端的预约可见性与干预能力：在「修改考试」页的时间段表里，每个预约型时段提供「查看预约」入口，弹窗列出已预约的部门 / 预约人 / 预约时间；并允许管理员（`sa`/`teacher`）取消任意部门的预约。管理员不受助理「时段开始前」的限制可随时取消，若被取消部门已有学员开考/交卷则二次确认。取消仅释放名额、阻止该部门之后开考，不删除已有试卷与成绩。

## Problem Frame

[预约考试特性](2026-05-29-exam-assistant-booking-requirements.md) 落地后，部门考试助理可自助认领时段，但管理端缺两块：

1. **看不到谁约了。** 后端虽已有按时段返回预约情况的接口（plan 001 的 U7，`/exam/api/exam/booking/slot-bookings`），但前端没有任何页面调用它，`sa`/`teacher` 在 UI 上无法查看某场考试各时段已被哪些部门预约、谁约的、何时约的。
2. **管不了误约。** 目前只有助理能取消**本部门**且**时段开始前**的预约；管理员无法取消任意部门的预约，遇到部门约错、临时调整、或已开始才发现的误约时没有兜底手段。

本特性补齐"看"与"取消"这两个管理端动作，让管理员对预约情况有可见性和最终干预权，与"考试本身仍由 `sa`/`teacher` 掌控"的定位一致。

## Actors

- **超级管理员 / 老师（`sa` / `teacher`）** — 在考试管理中查看某场考试各预约型时段的预约情况，并可取消任意部门的预约。
- **考试助理 / 学员** — 不受本特性新增 UI 影响；助理原有的自助预约/取消/改约能力不变；被取消部门的未开考学员会随之失去开考资格（动态判定）。

## Requirements

### 查看预约（管理端）
- VR1. 在「修改考试」页的时间段表中，每个**预约型**（open_type=3）时段显示「查看预约(N)」入口，N 为该时段已预约的部门数；非预约型时段不显示该入口。
- VR2. 点击后弹窗列出该时段每条预约的：部门名称、预约人（助理）姓名、预约时间，按预约时间排序。
- VR3. 查看能力对 `sa` 与 `teacher` 开放。

### 取消预约（管理端）
- CR1. 查看弹窗中每条预约行提供「取消」，由 `sa`/`teacher` 操作，移除该部门在本场该时段的预约并释放一个部门名额。
- CR2. 管理员取消不受助理「时段开始前」限制——已开始 / 已结束时段的预约也可取消。
- CR3. 取消前，若被取消部门在本场考试已有学员试卷（进行中或已交卷），弹二次确认提示后再执行。
- CR4. 取消仅影响**之后**的开考资格：已生成的试卷、成绩、错题不受影响（应考资格在开考时点动态判定，不依赖预约快照）。
- CR5. 取消成功后弹窗列表即时刷新，时段的"已约/上限"计数同步更新。

## Acceptance Examples

- AE1（VR1, VR2）某预约型时段被技术部、市场部预约，管理员在时段表看到「查看预约(2)」，点开弹窗显示两行，每行含部门名、预约人姓名、预约时间。
- AE2（CR1, CR5）`sa` 取消市场部的预约后，弹窗剩一行，该时段计数由 2/3 变为 1/3，市场部下属员工此后无法开考。
- AE3（CR2）某时段已到开始时刻，`sa` 仍可在弹窗中取消某部门的预约（助理此时已不能取消）。
- AE4（CR3, CR4）取消一个"已有学员交卷"的部门时弹出二次确认；确认后该部门已交卷的成绩与记录仍在，仅未开考的员工失去入口。
- AE5（VR3, CR1）以 `teacher` 身份同样能查看并取消预约。

## Scope Boundaries

- 取消的通知 / 提醒（站内信、短信、邮件）—— 不做，系统无通知设施（沿用预约特性既有非目标）。
- 取消原因填写与审计记录（谁取消、何时、为何）—— 不做，本次直接删除预约记录，与助理取消同机制。
- 管理员代部门预约 / 指派部门到时段 —— 不做；预约型时段的「免约部门」已覆盖"管理员直接指定可考部门"的需求。
- 免约部门的增删 —— 不在本特性，属编辑时段本身，走现有时段配置。
- 独立的预约统计 / 看板 —— 不做。

## Dependencies / Assumptions

- 依赖预约特性已交付的存储与接口：`el_exam_booking` 表、`slot-bookings` 查询接口（见 [plan 001](../../engineering/plans/2026-05-29-001-feat-exam-assistant-booking-plan.md) 的 U6/U7）。
- **权限放宽**：查看与取消对 `sa` 与 `teacher` 开放。现有 `slot-bookings` 端点当前为 `@RequiresRoles("sa")`，需放宽为"sa 或 teacher"；新增的管理员取消端点同样允许两者。注意：考试 `save` 端点仍限 `sa`——这是项目既有的角色不一致，本特性不改。
- **静默失去资格（已接受）**：管理员取消某部门后，该部门尚未开考的学员会无通知地失去开考入口——这是"不做通知"的直接后果。
- 取消为硬删除 `el_exam_booking` 记录，无审计留痕，与助理取消行为一致。
- UI 落点为「修改考试」页的时间段表（与时段配置同处），不新增独立页面或路由。

## Outstanding Questions

### 可在实现/规划阶段解决
- teacher 放宽的具体实现方式（Shiro `@RequiresRoles(logical=OR)` 或等价机制）。
- 「已有学员试卷」判定口径：默认"进行中"与"已交卷"两种都触发二次确认；如只想对某一种提示再调整。
- 取消后是否需要在弹窗中以提示语说明"已交卷成绩不受影响"，降低管理员误解（文案细节）。
