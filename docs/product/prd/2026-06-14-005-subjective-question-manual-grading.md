# 005 简答题与人工阅卷 · PRD

## 1. 背景与问题

当前系统只支持客观题：单选（`RADIO=1`）、多选（`MULTI=2`）、判断（`JUDGE=3`）、不定项（`UNCERTAIN=5`）、综合题（`COMPOSITE=6`），交卷即自动判分、即时出分（题型定义见 [`QuType.java`](../../../exam-api/src/main/java/com/yf/exam/modules/qu/enums/QuType.java)）。

原作者在底层**预留了主观题与人工阅卷的骨架，但从未接通**：试卷状态枚举有「待阅卷 `WAIT_OPT=1`」（见 [`PaperState.java`](../../../exam-api/src/main/java/com/yf/exam/modules/paper/enums/PaperState.java)）、`el_paper_qu` 有 `answer`（主观答案）与 `actual_score`（实际得分(主观题)）字段（见 [`PaperQu.java`](../../../exam-api/src/main/java/com/yf/exam/modules/paper/entity/PaperQu.java)）、`ExamController` 有「待阅卷列表」接口——但题型枚举里没有简答题（无 type 4），[`PaperController`](../../../exam-api/src/main/java/com/yf/exam/modules/paper/controller/PaperController.java) 里没有任何打分/阅卷接口，前端也没有阅卷页。这条链路是断的：一旦出现需人工评分的题，试卷会永远卡在客观自动判分这一步，无法收尾。

前序特性 [004 综合题与不定项](2026-06-04-004-composite-question-indefinite-choice.md) 明确把「主观题（type 4）与人工阅卷流程」列为非目标。本特性（005）正是接手 004 留下的这块：新增独立**简答题**（type 4）并接通**人工阅卷**，把「录题 → 组卷 → 作答 → 人工阅卷 → 算分出分」走成完整闭环。由于底层骨架已在，补全代价远小于从零新建。

## 2. 目标 / 非目标

### 目标
- 新增独立**简答题**题型（`type 4`）：含题干、参考答案、解析，无选项（分值在组卷按题型统一配置，与单选/多选同模式）；可在试题管理中录入/编辑/删除/筛选。
- 简答题可入题库、参与考试组卷与抽题；**组卷时简答题为可选项（数量可为 0）**。
- 考生端支持简答题作答（多行文本输入），随卷提交。
- 含简答题的试卷交卷后进入「待阅卷」；接通**整份试卷人工阅卷**：`sa`/`teacher` 逐题录入整数得分与可选文字点评，整份提交。
- 阅卷提交后系统重算总分（客观自动分 + 主观人工分）、判定通过与否，试卷转「已完成」，**考生即时可见**总分、逐题得分、参考答案与点评。

### 非目标
- **不**支持综合题包含简答子题：综合题维持纯客观、固定 5 子题、其自动判分逻辑不变（沿用 004）。
- **不**做按题集中阅卷（一次看全体考生同一题）；只做按整份试卷阅卷。
- **不**细分论述题等其他主观题型；简答题已覆盖文本作答需求。
- **不**支持简答题的 Excel 批量导入/导出（沿用 004 对新题型导入的推迟，首期仅手工录题）。
- **不**支持半分/小数分；单题得分为整数。
- **不**做「统一发布成绩」流程——阅完即可见。
- **简答题不纳入错题本与错题训练**：错题本现为客观题「对/错」二值采集，简答无明确对错，不参与采集。
- **成绩公开后不允许改分**：试卷阅完即「已完成」且考生已可见，首期不支持对已公开分数的二次回改。
- 阅卷**不按「考试归属」隔离**：不为考试新增创建人/归属字段，`sa` 与 `teacher` 一视同仁可阅全部待阅卷。

## 3. 用户与角色
- **录题/组卷人（`sa` / `teacher`）**：录入/编辑/删除简答题（题干、参考答案、解析）；组卷时可选地纳入简答题（数量可为 0）、并配置简答每题分值（saq_score）。沿用现有试题管理与考试配置权限，不新增角色。
- **阅卷人（`sa` / `teacher`）**：在「待阅卷试卷列表」打开试卷，逐题为简答打分、写点评，整份提交。二者均可阅任意待阅卷试卷。
- **考生（`student`）**：作答简答题（文本输入）；阅卷完成后查看总分、逐题结果、参考答案与老师点评。考生端无阅卷入口。

## 4. 关键决策
1. **只做独立简答题，综合题保持纯客观。** 简答作为独立 `type 4`，可入题库、组卷、单独成题；综合题 5 子题仍限客观题型，其全自动判分逻辑完全不动。把改动面收到最小，避免触碰已上线的综合题判分链。
2. **按整份试卷阅卷，而非按题集中阅卷。** 阅卷人打开某考生一份试卷，依次给其中所有简答题打分后整份提交，直接复用现有「待阅卷试卷列表」，不引入按题聚合的查询与页面。
3. **阅完即可见，不做「统一发布成绩」。** 阅卷人提交一份卷后，该考生立即可见总分与逐题结果，与现有客观卷「交卷即出分」体验一致；不引入额外的发布状态与操作。
4. **单题得分按整数。** 沿用现有 `actual_score` 为 `Integer` 的设计，阅卷打分取 `0..该题满分` 的整数；不支持半分/小数分。
5. **复用 `WAIT_OPT` 状态贯穿流转。** 含简答的试卷交卷后进入待阅卷；纯客观卷维持交卷即「已完成」不变。
6. **组卷时简答题可选、分值按题型统一配置。** 简答题数量可配置为 0（为 0 时等同纯客观卷）；简答每题满分在组卷处按题型统一设（`saq_score`），与单选/多选同模式，复用基线库已存在的 `el_exam_repo.saq_count`/`saq_score` 两列，**录题处不配分值**。
7. **简答题不计入客观分。** 简答按 `type 4`，其得分来自人工阅卷的 `actual_score`，不进入客观题自动汇总口径；客观分汇总口径需与新题型协调（具体取值与口径在 plan 核验，见 §11）。

## 5. 功能需求（R/F，续编不重排）

### 录题（试题管理）
- **R1** 作为录题人，我想在试题管理中新增「简答题」题型（`type 4`），以便录入需人工评分的文本作答题；列表与编辑应能按该题型筛选、回显。
- **R2** 作为录题人，我想为简答题录入题干、参考答案、解析（无选项；**不在录题处配分值**，分值在组卷按题型统一配置，见 R3），以便成题。题干/参考答案/解析的最大字符数按业务定值，并在前后端一致校验（前端 `maxlength`、后端按字符数前置校验）。

### 组卷与作答
- **R3** 作为管理员，我想让简答题像其他题型一样进入题库并参与组卷抽题，且**组卷时简答题数量可配置（含 0）、并按题型统一配置每道简答的分值（与单选/多选同模式，复用 `el_exam_repo.saq_count`/`saq_score`）**，以便按需把简答题纳入考试；数量为 0 时该考试不含简答题，按 R5 走「交卷即完成、即时出分」。
- **R4** 作为考生，我想在答题界面作答简答题（多行文本输入），其按现有答题卡分组规则归入「简答题」一组、支持已答/未答标记与跳转；作答内容随作答实时保存到该题主观答案，「已答」判定为作答文本非空。

### 判分与状态流转
- **R5** 当考生提交含简答题的试卷时，系统应先对客观题自动判分，并因含未判简答题将试卷置为「待阅卷」、此时不产出总分；纯客观试卷维持交卷即「已完成」、即时出分，不受影响。
- **R6** 当考生提交纯简答（无客观题）的试卷时，系统应将客观得分计为 0、整卷置为「待阅卷」，待阅卷后出分。

### 人工阅卷
- **R7** 作为阅卷人（`sa`/`teacher`），我想打开一份待阅卷试卷，看到其中每道简答题的题干、考生作答、参考答案与解析，并为每题录入整数得分（`0..该题满分`）与可选文字点评，整份提交，以便完成评分。
- **R8** 若阅卷提交时存在简答题未录入得分，或某题得分不在 `[0, 该题满分]` 区间内，则系统应拒绝提交并提示原因。
- **R9** 当阅卷人整份提交后，系统应将试卷总分计为「客观题自动得分 + 各简答题人工得分之和」，按总分与该考试及格线判定通过/不通过，并将试卷转为「已完成」。

### 成绩呈现与权限
- **R10** 当阅卷提交后，考生应能即时在成绩列表/成绩详情看到总分、逐题得分、参考答案与老师点评，无需管理员额外发布。
- **R11** 阅卷打分能力限 `sa` 与 `teacher`，二者均可阅任意待阅卷试卷；待阅卷列表/阅卷入口对 `sa`/`teacher` 可见，考生端无阅卷入口。

## 6. 非功能约束
- **兼容性**：现有客观题（单选/多选/判断/不定项/综合）的录入、组卷、判分行为不得改变；存量试题与试卷不受影响；综合题判分链不被触碰。
- **判分模型一致性**：总分 = 客观自动分 + 主观人工分之和；同一份卷重复结算结果一致（确定性）。客观分汇总口径需与新题型 `type 4` 协调，确保简答题不被计入客观自动分（其分由人工 `actual_score` 提供）。
- **字段长度全链路一致**：题干/参考答案/解析/点评的最大字符数以业务最大字符数为唯一真值，后端按字符数前置校验、前端 `maxlength`、接口文档三处对齐（参工程宪法 #9）。
- **权限**：录题/组卷沿用现有试题管理与考试配置鉴权（`sa`/`teacher`）；阅卷接口限 `sa`/`teacher`，不向 `assistant`/`student` 开放。
- **依赖**：不引入新第三方依赖；遵循 [`conventions.md`](../../engineering/conventions.md) 的命名/分层/前端约定。
- **数据库变更**：落 `docs/ops/install/migration-2026-subjective-grading.sql`，与 design/plan 的 ER 模型逐字段一致，含回滚段、`COMMENT`、`create_time`/`update_time`（按既有表约定）。

## 7. 验收标准（AE/AC，每条标注覆盖的需求号）
- **AE1（R1）** 试题新增页题型下拉含「简答题」；选择后录入题干/参考答案/解析/分值（无选项区）可保存成功；列表可按「简答题」筛选，编辑回显题型为简答题。
- **AE2（R2）** 题干/参考答案/解析超出设定最大字符数时，前端阻止输入、后端拒绝保存并提示；在限内可正常保存。
- **AE3（R3）** 组卷配置可设「简答题」抽取数量 N（可为 0）与每题分值（saq_score）；N>0 时生成试卷恰含 N 道简答题、每题满分取该 saq_score；N=0 时试卷不含简答题且按 AE2-纯客观路径（交卷即完成、即时出分）。
- **AE4（R4）** 考生作答页：简答题渲染为多行文本框，归入答题卡「简答题」分组；输入后标记为「已答」、清空后回到「未答」；作答内容在切题/刷新后仍保留。
- **AE5（R5、R9）** 一场 100 分考试 = 客观题 70 分 + 2 道简答各 15 分。考生客观题自动得 55，交卷后试卷为「待阅卷」、成绩列表显示「待阅卷」、不显示总分；阅卷人给两道简答 12 与 9，提交后总分 = 55 + 12 + 9 = 76，与及格线比对判定后试卷转「已完成」。
- **AE6（R6）** 一场纯简答考试（无客观题）：考生交卷后客观得分为 0、整卷「待阅卷」；阅卷出分后转「已完成」。
- **AE7（R7）** 阅卷人在待阅卷列表打开一份卷，可见每道简答的题干、考生作答、参考答案、解析；为每题录入得分与点评后整份提交成功。
- **AE8（R8）** 阅卷人对某简答（满分 15）误填 18，或留空未评即点提交，系统拒绝提交并提示该题得分非法/未评；改为合法值后可提交。
- **AE9（R10）** 阅卷人整份提交后，该考生刷新成绩即可看到总分、每道简答的得分、参考答案与老师点评；无需管理员额外发布。
- **AE10（R11）** `sa`/`teacher` 能看到并进入待阅卷列表为任意待阅卷试卷打分；`student`（及 `assistant`）无阅卷入口、无法调用阅卷接口。

## 9. 成功指标
- 录题人能成功创建一道简答题（含参考答案、解析、分值）并将其纳入一场考试（含「组卷简答数=0」与「>0」两种配置均行为正确）。
- 考生作答含简答的试卷后，试卷正确进入「待阅卷」；`sa`/`teacher` 整份阅卷后，系统正确算出「客观分 + 主观分」总分并判定通过与否，§7 全部 AE 通过。
- 现有客观题（含综合题/不定项）的录入、组卷、判分回归无新增问题。

## 10. 依赖与假设
- 复用既有底层资产：`PaperState.WAIT_OPT`（待阅卷）、`el_paper_qu.answer`（主观答案）与 `el_paper_qu.actual_score`（实际得分(主观题)）、`ExamController` 的待阅卷列表接口。
- 假设现有交卷流程（[`PaperServiceImpl.handExam`](../../../exam-api/src/main/java/com/yf/exam/modules/paper/service/impl/PaperServiceImpl.java)）可扩展出「含主观题→置为待阅卷、纯客观→直接完成」的分支（待 design 核验，若无则补）。
- 假设成绩详情页与答题卡已有逐题渲染/分组框架，扩展简答题展示（作答/参考答案/解析/点评）与文本输入控件即可，不新建结果页。
- 假设题型下拉、筛选过滤器（`exam-vue/src/filters`）、录题表单可扩展承载简答题（无选项编辑区）。

## 11. 待解决问题
- **题型编码与客观分汇总口径**：简答取 `type 4`；需确认客观分汇总（如 `PaperQuMapper.sumObjective` 的 `qu_type` 口径）将简答正确排除在客观自动分之外、其分仅来自人工 `actual_score`，避免重复计分或漏计（留待 design/plan）。
- **点评与文本字段最大长度定值**：题干/参考答案/解析/点评的具体最大字符数，待原型/设计阶段按业务定值并贯穿前后端校验。
- **阅卷页形态**：阅卷界面新建独立页还是复用试卷详情页扩展，留待原型/设计确定。
- **待阅卷列表现状**：`ExamController` 的 review-paging 现状是否完整可用（筛选/分页/权限），待 design 核验，缺则补。
- **点评存储位置**：「点评/批注」字段挂在 `el_paper_qu`（按题存）还是另存，具体 ER 与字段在 design/plan 定。
